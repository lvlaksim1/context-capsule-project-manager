# Context Capsule v1.3 hardening scope

## Product outcome

A fresh chat or agent with no conversation history must be able to restore the project from the target repository and identify the next concrete action.

Installing or maintaining Context Capsule must not damage existing project context.

## Permanent capabilities

1. Clean installation into a repository that does not already have a capsule.
2. Repository-local durable semantic context.
3. Structural validation (`VALID`) separated from recovery readiness (`READY`).
4. Deterministic bounded fresh-chat recovery from repository content only.
5. Safe repository-path confinement.
6. Preservation of project-owned manifest extensions and instructions.
7. Managed Context Capsule blocks inside shared bootstrap files.
8. Exact Core provenance by immutable commit SHA.
9. Atomic GitHub publication from an expected parent.
10. Non-destructive repair of an installed v1.3 capsule.

## Completed transition

The temporary legacy bridge was used once for:

- `lvlaksim1/ai-agent-lab`;
- `lvlaksim1/fgis-fsa-il`;
- `lvlaksim1/telegram-receiver`.

After all three migrations were verified against their live Git trees, the repository-specific adapter and `adopt` CLI were removed. Their historical implementation remains available through Git history, not the normal product surface.

## Out of scope

- Windows-specific filesystem compatibility work;
- local lock-file / rollback-journal infrastructure as the primary safety model;
- a new event-log memory model;
- a permanent framework for arbitrary unknown legacy capsule formats;
- telemetry, a central registry, or reverse synchronization of target context.
